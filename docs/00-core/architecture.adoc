== Architecture

[.lead]
The current code uses four package layers. The foundation is intentionally incomplete at
the HTTP use-case level: DTOs, persistence, and mapping exist, while Discord resources and
application services begin in ticket #17.

=== Implemented Layers

[cols="1,2,4",options="header",stripes=odd]
|===
|Layer |Current package |Implemented responsibility

|*API*
|`org.acme.discord.api`
|Generic exception mappers for conflict, domain validation, unexpected exceptions,
Jackson errors, and missing values. There are no Discord JAX-RS resources yet.

|*Application*
|`org.acme.discord.application`
|Create, full-update, and response DTO records for User, Guild, Role, and Channel. There
are no Discord application services yet.

|*Domain*
|`org.acme.discord.domain`
|Framework-independent records `User`, `Guild`, `Role`, and `Channel`, plus the
`ChannelType` enumeration.

|*Infrastructure*
|`org.acme.discord.infrastructure`
|JPA entities, UUID Panache repositories, and dedicated mappers for the four resources.
|===

[NOTE]
====
All project Java layers use the canonical `org.acme.discord` package.
====

=== Enforced Dependency Rules

`LayerArchitectureTest` preserves the existing ArchUnit rules:

* API may access only Application;
* Application may access Domain and Infrastructure;
* Infrastructure may access Domain and Application;
* Domain may not access another project layer;
* Application and API implementation classes must remain stateless.

`DomainIsolationTest` separately rejects framework and infrastructure dependencies from
the domain. `NamingConventionTest` enforces package-specific class suffixes.

=== Key Design Decisions

[cols="1,3,4",options="header",stripes=odd]
|===
|Decision |Choice |Rationale

|Identifiers
|UUID generated by JPA
|IDs remain server-managed and are consistent across the four persistence resources.

|Dates
|UTC `LocalDateTime` generated by User and Guild mappers
|Preserves the existing model type while removing dependence on the host or injected clock
zone.

|Relations in responses
|UUID values and immutable UUID snapshots
|Prevents JPA entities and Hibernate collections from crossing the future API boundary.

|Persistence access
|Panache repositories with `PanacheRepositoryBase<Entity, UUID>`
|Keeps queries and persistence lifecycle outside domain records and mappers.

|Validation
|Jakarta Bean Validation on request records and entities
|Aligns incoming contracts with persistence constraints before future service logic runs.

|Integration database
|Ephemeral PostgreSQL via Testcontainers
|Exercises PostgreSQL relationship and constraint behavior without touching the persistent
project database.
|===
