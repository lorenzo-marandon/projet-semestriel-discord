== Verified Non-Functional Requirements

[.lead]
This section records constraints supported by the current code and automated tests. It
does not claim behavior for the Discord CRUD REST layer planned in ticket #17.

=== Architecture

[[nfr-arch-01]]
==== NFR-ARCH-01 — Framework-independent domain

The domain package must not depend on Quarkus, JPA, Hibernate, REST, or infrastructure
classes.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`DomainIsolationTest`
|Checks framework independence and prevents domain-to-infrastructure dependencies.
|===

[[nfr-arch-02]]
==== NFR-ARCH-02 — Controlled layer dependencies

Dependencies between API, application, domain, and infrastructure packages must satisfy
the rules encoded in ArchUnit. Application and API classes other than DTO/request records
must expose only final fields.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`LayerArchitectureTest`
|Checks layer access and statelessness rules.
|`NamingConventionTest`
|Checks Resource, Entity, Repository, DTO, Mapper, Filter, and Client suffixes whenever
matching classes exist.
|===

=== Data and Contracts

[[nfr-data-01]]
==== NFR-DATA-01 — PostgreSQL mapping integrity

Discord entities and their guild membership, role assignment, role ownership, and channel
ownership relationships must persist and reload correctly in PostgreSQL.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`DiscordPersistenceIT`
|Runs entity and relationship scenarios against an ephemeral PostgreSQL Testcontainer.
|`PostgreSqlTestResource`
|Starts PostgreSQL and supplies the test datasource configuration.
|===

[[nfr-data-02]]
==== NFR-DATA-02 — Validated input contracts

Required text, enum, position, and guild identifier fields must be rejected when invalid.
Server-managed IDs and dates must not be request components.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`RequestValidationTest`
|Checks valid requests, blank values, null values, negative positions, and record
components.
|===

[[nfr-data-03]]
==== NFR-DATA-03 — UTC server dates

User join dates and guild creation dates generated by mappers must represent the supplied
instant in UTC, independent of the clock's zone. Updates must retain those dates.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`UserMapperTest`, `GuildMapperTest`
|Check UTC and Europe/Paris clocks, default server clocks, and update preservation.
|===

=== Operations and Documentation

[[nfr-ops-01]]
==== NFR-OPS-01 — Health and OpenAPI availability

Quarkus must expose liveness, readiness, aggregate health, Health UI, and the generated
OpenAPI document. The OpenAPI document currently contains only the implemented technical
surface; Discord CRUD paths are not expected yet.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`TechnicalSpecsIT`
|Checks `/q/health/live`, `/q/health/ready`, `/q/health-ui/`, and `/q/openapi`.
|`application.properties`
|Configures Swagger UI at `/swagger-ui` and stores generated schemas under
`target/openapi-spec`.
|===

[[nfr-ops-02]]
==== NFR-OPS-02 — Reproducible technical documentation

The Maven `docs` profile must render the canonical `docs/index.adoc` source and its local
PlantUML diagrams to both HTML and PDF.

[cols="1,3",options="header"]
|===
|Evidence |Coverage
|`mvn verify -Pdocs`
|Produces `target/living-docs/html/index.html` and
`target/living-docs/pdf/index.pdf`.
|===
